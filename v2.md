# V2 Specification — Production-Oriented 2D Human Review Tool

> **Status:** Design baseline / Single Source of Truth  
> **Version:** V2  
> **Scope:** 2D Computer Vision Dataset Human Review  
> **Primary input:** COCO dataset + actual image files  
> **Storage:** SQLite + local filesystem  
> **Core principle:** QA creates signals; humans create decisions.

---

## 1. Purpose

V2 evolves the V1 rule-based dataset QA tool into a production-oriented 2D Human Review Tool.

Core workflow:

```text
Import Dataset
      ↓
Validate Dataset
      ↓
Create Dataset Version
      ↓
Run QA
      ↓
Generate QA Issues
      ↓
Build Review Queue
      ↓
Reviewer opens Review Item
      ↓
2D Viewer inspection
      ↓
ACCEPT / REJECT / NEEDS_FIX
      ↓
Review History + Audit
      ↓
Export Results
```

V2 focuses on:
- 2D bounding boxes
- 2D polygons
- segmentation: Polygon + RLE
- 2D visualization
- deterministic QA
- human review workflow
- dataset versioning
- history, audit, and export

V2 is a review tool, not an annotation editor.

---

## 2. Goals

V2 MUST:
1. Import real COCO datasets and actual image files.
2. Validate annotation data and image files.
3. Normalize COCO into a canonical internal 2D model.
4. Represent BBox, Polygon, and Segmentation independently of raw COCO.
5. Run deterministic QA rules.
6. Convert QA issues into a review queue.
7. Provide a 2D review workspace.
8. Support ACCEPT / REJECT / NEEDS_FIX.
9. Persist review history and audit events.
10. Use immutable dataset versions.
11. Export review results.
12. Provide unit, integration, API, and E2E tests.

Design philosophy:

```text
QA = signal
Viewer = inspection tool
Human = decision maker
Dataset Version = immutable snapshot
Audit = historical trace
Export = read-only output
```

---

## 3. Out of Scope

V2 initial implementation does NOT include:
- AI / LLM
- auto-labeling
- automatic annotation correction
- automatic human decisions
- pose / keypoints
- face landmarks
- 3D / point clouds
- tracking
- ADAS-specific logic
- CVAT integration
- real-time multi-user collaboration
- authentication / authorization
- cloud deployment
- S3 / object storage
- PostgreSQL
- Kubernetes
- mobile UI
- annotation editing
- semantic image understanding

# 5. Geometry Model

## 5.1 Coordinate system

```text
coordinateSpace = IMAGE_PIXEL
origin = top-left
```

Viewer zoom/pan MUST NOT mutate canonical coordinates.

## 5.2 Hierarchy

```text
Geometry
├── BBOX
│   ├── x
│   ├── y
│   ├── width
│   └── height
├── POLYGON
│   └── points[]
│        └── Point2D(x, y)
└── SEGMENTATION
    ├── encoding: POLYGON
    │    └── polygons[]
    │         └── points[]
    └── encoding: RLE
         └── rle
```

## 5.3 BBox

Canonical representation:

```json
{"x":100,"y":200,"width":80,"height":120}
```

Derived values:
- x2
- y2
- area
- bounds

Expected operations:

```text
getX2()
getY2()
getArea()
getBounds()
containsPoint()
isValid()
```

Source of truth is `x, y, width, height`.

## 5.4 Polygon

```text
Polygon
└── points[]
      ├── Point2D
      ├── Point2D
      └── ...
```

Expected operations:

```text
getBounds()
getArea()
getPerimeter()
containsPoint()
isValid()
hasSelfIntersection()
```

Validation SHOULD cover:
- too few points
- non-finite coordinates
- duplicate consecutive points
- zero area
- degenerate polygon
- self-intersection
- out-of-image coordinates

Polygon closure is logical; repeated first point is not required.

## 5.5 Segmentation

V2 MUST support:
- Polygon encoding
- RLE encoding

RLE MUST preserve its semantics. Rendering may decode RLE to a mask; it must not require RLE → Polygon conversion.

- fine-grained visual judgement

# 8. Review Workflow

Status:

```text
UNREVIEWED
IN_REVIEW
REVIEWED
```

Decision:

```text
ACCEPT
REJECT
NEEDS_FIX
```

Valid combinations:

| Status | Decision |
|---|---|
| UNREVIEWED | NULL |
| IN_REVIEW | NULL |
| REVIEWED | ACCEPT |
| REVIEWED | REJECT |
| REVIEWED | NEEDS_FIX |

State machine:

```text
UNREVIEWED
     │ start
     ▼
IN_REVIEW
     │ submit(decision)
     ▼
REVIEWED
```

Closing the browser does not imply REVIEWED.

## 8.1 NEEDS_FIX

NEEDS_FIX does not auto-edit annotations.

```text
Reviewer
 ↓
NEEDS_FIX
 ↓
Export NEEDS_FIX
 ↓
External annotation fix
 ↓
New DatasetVersion
 ↓
QA
 ↓
Re-review
```

## 8.2 Review history

```text
ReviewHistory
├── id
├── reviewItemId
├── datasetVersionId
├── reviewRound
├── status
├── decision
├── note
├── reviewerId
├── reviewerName
└── timestamp
```

History is append-only.

## 8.3 Review round

A review round is an evaluation context associated with a dataset version, not the number of submits.

```text
V1 → Round 1 → NEEDS_FIX
      ↓
external fix
      ↓
V2 → Round 2
```

A new version creates a new review context. Old ACCEPT decisions are not automatically current decisions for the new version.



# 23. Business Invariants

## Dataset / Version

```text
INV-01
(dataset_id, version_number) is unique.

INV-02
parent_version_id, if present, belongs to the same Dataset.

INV-03
A version cannot be its own parent.

INV-04
Version lineage cannot contain cycles.

INV-05
READY DatasetVersion is immutable.
```

## Image / Annotation

```text
INV-06
Annotation belongs to exactly one DatasetVersion.

INV-07
Annotation.image_id references an Image in the same DatasetVersion.

INV-08
Image paths are relative paths, not machine-specific absolute paths.
```

## QA

```text
INV-09
QAIssue belongs to its QARun and DatasetVersion.

INV-10
If QAIssue.annotation_id exists, the annotation belongs to the same version.

INV-11
QA severity never directly becomes a human decision.
```

## Review

```text
INV-12
UNREVIEWED → decision must be NULL.

INV-13
IN_REVIEW → decision must be NULL.

INV-14
REVIEWED → decision is REQUIRED.

INV-15
Successful review submission creates ReviewHistory.

INV-16
Successful review submission creates AuditEvent.

INV-17
ReviewHistory is append-only.

INV-18
Review does not mutate annotation geometry/category.
```

## Version / Review

```text
INV-19
A ReviewItem always belongs to exactly one DatasetVersion.

INV-20
A new DatasetVersion creates a new review context.

INV-21
An old ACCEPT decision is not automatically current for a new version.
```

## Export

```text
INV-22
Export is read-only with respect to the dataset.

INV-23
Every ExportJob stores its filter snapshot.

INV-24
Export artifacts are linked to the ExportJob.
```

## Storage

```text
INV-25
SQLite stores application/domain state.

INV-26
Filesystem stores image and artifact binaries.

INV-27
Images are not stored as SQLite blobs in V2.

INV-28
Audit events are append-only.
```

## Geometry / Viewer

```text
INV-29
Canonical geometry uses IMAGE_PIXEL coordinates.

INV-30
Viewer zoom/pan does not mutate canonical geometry.

INV-31
RLE segmentation retains RLE semantics.

INV-32
Storage JSON representation is not the Domain representation.
```

## Review grouping

```text
INV-33
Multiple QA issues for the same annotation/version normally map to one ReviewItem.

INV-34
Annotation grouping uses:
(datasetVersionId, imageId, annotationId).

INV-35
Image-level grouping uses:
(datasetVersionId, imageId, null).
```

## Progress

```text
INV-36
Review progress counts only REVIEWED ReviewItems.
IN_REVIEW is not completed.
```

# 24. Atomic Review Submit

Successful submit MUST behave as one transaction:

```text
BEGIN
    Update ReviewItem
    Insert ReviewHistory
    Insert AuditEvent
COMMIT
```

Any failure:

```text
ROLLBACK
```

The system must not leave a partially committed review.

# 27. Implementation Principles

1. **Canonical model first**

```text
COCO
 ↓
Adapter
 ↓
Canonical Domain Model
 ↓
Everything else
```

2. **QA is not decision**

```text
QA Signal
   ↓
Human inspection
   ↓
Human decision
```

3. **Version is immutable**

```text
Fix
 ↓
New Version
```

4. **Viewer is not source of truth**

```text
Canonical Geometry
       ↓
Viewer
```

5. **History is append-only**

```text
Current state = mutable
History = immutable
Audit = immutable
```

6. **Business transactions are atomic**

Review submission and dataset import must not leave partially committed state.
