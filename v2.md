## 1. Mục đích (Purpose)

V2 phát triển công cụ QA dataset rule-based của V1 thành một **công cụ Human Review 2D hướng production**.

Core workflow:

```text
Import Dataset
      ↓
Validate Dataset
      ↓
Create Dataset Version
      ↓
Run QA
      ↓
Generate QA Issues
      ↓
Build Review Queue
      ↓
Reviewer opens Review Item
      ↓
2D Viewer inspection
      ↓
ACCEPT / REJECT / NEEDS_FIX
      ↓
Review History + Audit
      ↓
Export Results
```

V2 tập trung vào:
- 2D bounding boxes
- 2D polygons
- segmentation: Polygon + RLE
- 2D visualization
- deterministic QA
- human review workflow
- dataset versioning
- history, audit, and export

V2 là công cụ review, **không phải** annotation editor.

---

## 2. Mục tiêu (Goals)

V2 MUST:
1. Import real COCO datasets and actual image files.
2. Validate annotation data and image files.
3. Normalize COCO into a canonical internal 2D model.
4. Represent BBox, Polygon, and Segmentation independently of raw COCO.
5. Run deterministic QA rules.
6. Convert QA issues into a review queue.
7. Provide a 2D review workspace.
8. Support ACCEPT / REJECT / NEEDS_FIX.
9. Persist review history and audit events.
10. Use immutable dataset versions.
11. Export review results.
12. Provide unit, integration, API, and E2E tests.

Design philosophy:

```text
QA = signal
Viewer = inspection tool
Human = decision maker
Dataset Version = immutable snapshot
Audit = historical trace
Export = read-only output
```


## 5.2 Phân cấp (Hierarchy)

```text

│   ├── y
│   ├── width
│   └── height
├── POLYGON
│   └── points[]
│        └── Point2D(x, y)
└── SEGMENTATION
    ├── encoding: POLYGON

    │         └── points[]
```

## 5.3 BBox

Biểu diễn canonical:

```json
{"x":100,"y":200,"width":80,"height":120}
```

Giá trị dẫn xuất:
- x2
- y2
- area
- bounds

Các operation dự kiến:

```text
getX2()
getY2()
getArea()
getBounds()
containsPoint()
isValid()
```

Nguồn chân lý là `x, y, width, height`.

## 5.4 Polygon

```text
Polygon
└── points[]
      ├── Point2D
      ├── Point2D
      └── ...
```

Các operation dự kiến:

```text
getBounds()
getArea()
getPerimeter()
containsPoint()
isValid()
hasSelfIntersection()
```

Validation NÊN bao gồm:
- too few points
- non-finite coordinates
- duplicate consecutive points
- zero area
- degenerate polygon
- self-intersection
- out-of-image coordinates

Việc đóng polygon mang tính logic; không bắt buộc lặp lại điểm đầu tiên.

## 5.5 Segmentation

V2 MUST support:
- Polygon encoding
- RLE encoding

RLE MUST preserve its semantics. Rendering may decode RLE to a mask; it must not require RLE → Polygon conversion.

## 5.6 Phase 3 Geometry Contract (Hợp đồng Geometry cho Phase 3)

> **Trạng thái:** đây là **contract thiết kế** cho Phase 3 (Geometry). Phần này CHƯA được
> triển khai; nó định nghĩa hành vi bắt buộc để hiện thực Phase 3 theo hướng production.
> Các normative block dưới đây giữ nguyên văn tiếng Anh.

Phase 2 đã thiết lập **cấu trúc dữ liệu geometry (data only)** và các guard cấu trúc tại thời
điểm khởi tạo (construction-time). Phase 3 bổ sung các phép tính dẫn xuất (derived) và một
**geometry validation contract** không ném lỗi. Ranh giới: Geometry chỉ tạo *facts*; QA
(Phase 4) mới gán severity và tạo QA Issue.

### 5.6.1 Coordinate contract

```text
coordinateSpace = IMAGE_PIXEL   (fixed)
origin          = top-left
units           = pixels
```

- Canonical coordinates live in IMAGE_PIXEL space and never depend on viewer transform.
- Image dimensions MUST NOT be embedded in the canonical geometry representation.

### 5.6.2 BBox contract

Canonical source of truth: `x, y, width, height`.

Derived values (computed, never stored as canonical truth):

```text
x2 = x + width      (exclusive right boundary)
y2 = y + height     (exclusive bottom boundary)
area   = width * height
bounds = { x, y, x2, y2 }
```

Example: x = 100, width = 80  =>  x2 = 180.

Validity classification:

```text
INVALID     : any of x, y, width, height is non-finite (NaN / Infinity)
INVALID     : width < 0 OR height < 0
DEGENERATE  : width == 0 OR height == 0 (finite, non-negative coordinates)
VALID       : width > 0 AND height > 0 AND all coordinates finite
```

Being outside the image is NOT malformed geometry (see 5.6.7).

### 5.6.3 Polygon contract

```text
Polygon = ordered list of Point2D
```

- A polygon MUST contain at least **3 DISTINCT points**. Raw length (`points.length >= 3`)
  is NOT sufficient; repeated points do not increase the distinct-point count.
- Closure is **logical**: repeating the first point is NOT required. The canonical
  representation SHOULD NOT require a repeated first point. A trailing point equal to the
  first (e.g. `A -> B -> C -> A`) MAY be canonicalized to `A -> B -> C`. This is the ONLY
  permitted duplicate-endpoint case; do not introduce a contradictory closure rule.
- **Consecutive duplicate points** (e.g. `A -> B -> B -> C`) are an INVALID polygon structure.

Validity classification:

```text
INVALID     : any non-finite coordinate
INVALID     : fewer than 3 distinct points
INVALID     : a consecutive duplicate point (excluding the logical-closure endpoint)
DEGENERATE  : 3+ distinct points but zero area (collinear), e.g. A(0,0) B(10,0) C(20,0)
VALID       : 3+ distinct points, non-zero area, structurally sound
```

Structural invalidity and geometric degeneracy are kept conceptually separate.

`hasSelfIntersection()` semantics:

- MUST detect intersections/overlaps between **non-adjacent** polygon edges.
- Normal adjacent-edge vertex sharing is NOT self-intersection.
- The closing edge and the first/last vertex relationship follow normal polygon adjacency.

```text
A -> B -> C -> D -> A   : adjacent connections allowed (not self-intersection)
A -> B -> C -> D        : non-adjacent edges crossing (bow-tie) => selfIntersection = true
```

The Geometry layer defines detection semantics only; it assigns no QA severity or decision.

### 5.6.4 Segmentation contract

```text
Segmentation
├── encoding = POLYGON  -> polygons[] (see 5.6.3)
└── encoding = RLE      -> rle        (see 5.6.5)
```

- V2 MUST support both Polygon and RLE encodings.
- Polygon-encoded segmentation follows the Polygon contract per ring.

### 5.6.5 RLE contract

Canonical RLE representation:

```text
RLE
├── counts
└── size = [height, width]     (COCO semantics: [height, width])
```

Already established by the Phase 2 implementation (do not re-open):

```text
- size MUST be an array of exactly two finite numbers [height, width].
- counts MUST be either a string OR an array of numbers.
- RLE is preserved as-is; it is NEVER canonicalized into Polygon (INV-31).
- Structurally malformed RLE (missing / non-length-2 / non-finite size, or counts that is
  neither string nor number array) is rejected at construction time.
```

Phase 3 requirements (NOT established in Phase 2 — implement in Phase 3):

```text
- RLE dimensions MUST be positive (height > 0 AND width > 0); non-positive dimensions are a
  STRUCTURAL violation rejected at construction (throw), not a validate() result (see 5.6.8).
- RLE decoding to a mask is an on-demand runtime operation: RLE -> runtime mask.
- The decoded mask is NOT the canonical persisted geometry.
- Malformed / undecodable RLE counts, discovered during decode(), yield an INVALID validation
  result at that runtime boundary (see 5.6.6 status meanings and 5.6.8 layering).
```

> NOTE: Phase 2 accepts `counts` as a string OR a number array and preserves it verbatim; it
> does NOT decode counts or verify decodability. Any claim about which `counts` values are
> *decodable* is a Phase 3 concern, not an existing Phase 2 capability.

### 5.6.6 Geometry validation contract

`validate()` chạy **sau khi** một canonical Geometry object đã được construct thành công. Nó
đánh giá **semantics** của geometry, không đánh giá lại tính hợp lệ cấu trúc cơ bản — cấu trúc
đã được constructor/factory bảo đảm (xem 5.6.8). `validate()` không throw và không mang trạng
thái QA/Review. Đây là một non-throwing validation result, phân biệt với các structural guard
tại thời điểm construction đã tồn tại từ Phase 2:

```text
GeometryValidationResult
├── status  : VALID | DEGENERATE | INVALID
└── issues[]: GeometryIssue

GeometryIssue.code (initial set):
- NON_FINITE_COORDINATE
- TOO_FEW_POINTS
- DUPLICATE_CONSECUTIVE_POINT
- ZERO_AREA
- SELF_INTERSECTION
- INVALID_BBOX_DIMENSION
- INVALID_RLE
```

Status meanings (ý nghĩa từng status — normative):

```text
VALID       - geometry satisfies structural AND semantic geometry requirements.
DEGENERATE  - geometry is structurally representable but geometrically degenerate
              (e.g. zero-dimension BBox, zero-area / collinear polygon).
INVALID     - a validation boundary or runtime operation cannot establish a valid
              geometry result, such as malformed / undecodable RLE during decoding.
              INVALID does NOT mean a structurally invalid canonical Geometry object is
              normally allowed to exist: structural violations are rejected at construction
              (constructor/factory throws — see 5.6.8), not surfaced as a validate() status.
```

Status precedence: INVALID > DEGENERATE > VALID.

Phân biệt nguồn gốc của từng issue code (để tránh nhập nhằng giữa ba biên: construction /
semantic / runtime):

```text
- Structural codes (NON_FINITE_COORDINATE, TOO_FEW_POINTS, DUPLICATE_CONSECUTIVE_POINT,
  INVALID_BBOX_DIMENSION, structural INVALID_RLE): these conditions are rejected at the
  STRUCTURAL boundary (constructor / parse / normalize throws). They may be reported by a
  pre-construction validation of raw / untrusted input, but they never describe a successfully
  constructed canonical object.
- Semantic codes (ZERO_AREA, SELF_INTERSECTION): produced by validate() on an already
  constructed canonical object; drive the DEGENERATE status.
- Runtime code (INVALID_RLE during decode): produced at the runtime decode boundary; drives
  the INVALID status when a mask cannot be established.
```

Geometry validation produces DERIVED FACTS ONLY. It MUST NOT contain QA severity, review
decision, reviewer state, or human judgment.

### 5.6.7 Geometry vs QA boundary

```text
Geometry
    ↓
Geometry validation / derived facts   (VALID / DEGENERATE / INVALID, isWithin(imageBounds))
    ↓
QA rules                              (Phase 4)
    ↓
QA Issue + severity
    ↓
Review Item / human decision
```

- Geometry validity and image-bound validity are SEPARATE concerns.
- A geometry MAY be structurally VALID while partially or fully outside the image.
- Geometry APIs MAY expose an image-bound check, e.g. `isWithin(imageBounds)` (or equivalent),
  taking image bounds as an argument — never storing them in canonical geometry.
- Phase 4 QA decides whether out-of-bounds geometry becomes a QA Issue and its severity.

### 5.6.8 Validation layering & architectural boundary (Decision #9)

Bốn tầng trách nhiệm (four responsibility layers) được tách bạch rõ ràng. Câu tuyên bố nền tảng
(normative, giữ nguyên văn):

```text
Constructor protects structure.
validate() evaluates geometry semantics.
QA evaluates dataset-quality implications.
Review evaluates human decisions.
```

Đây là một **ranh giới kiến trúc (architectural boundary)**, KHÔNG phải tuyên bố rằng Phase 3 đã
được triển khai. Phase 3 hiện ở trạng thái NOT STARTED.

**Layer 1 — Constructor / structural invariants.** Một canonical Geometry object KHÔNG được tồn
tại với dữ liệu cấu trúc không hợp lệ. Constructor/factory chịu trách nhiệm bảo vệ structural
invariant và **reject / throw** khi vi phạm:

```text
BBox:
- negative width / negative height        -> throw
- non-finite x / y / width / height       -> throw

Polygon:
- points is not an array                  -> throw
- malformed point structure               -> throw
- non-finite coordinates                  -> throw
- fewer than 3 distinct points            -> throw
- consecutive duplicate points            -> throw

RLE:
- invalid size structure                  -> throw
- invalid size dimensions                 -> throw
- invalid counts type                     -> throw
```

Constructor rejection là một STRUCTURAL violation, KHÔNG phải là một human review decision.

```text
UNTRUSTED INPUT
      ↓
Parse / Normalize
      ↓
Geometry Constructor / Factory
      ├── structural violation -> reject / throw
      ↓
Canonical Geometry
```
**Layer 2 — validate() geometry semantics.** Sau khi object đã được construct thành công,
`validate()` đánh giá **semantics** (xem 5.6.6) và trả về VALID hoặc DEGENERATE: BBox
zero-dimension => DEGENERATE; polygon zero-area / collinear => DEGENERATE; self-intersection
phát hiện theo semantics non-adjacent-edge đã duyệt. Các điều kiện semantic này KHÔNG bị biến
thành QA severity hay Review decision trong Geometry layer.

**Layer 3 — role of INVALID.** `INVALID` vẫn nằm trong từ vựng validation; nó dùng cho một
validation boundary hoặc runtime operation không thể thiết lập một kết quả geometry hợp lệ
(ví dụ điển hình: decode một RLE hỏng / không giải mã được). `INVALID` KHÔNG có nghĩa là một
canonical object cấu trúc-sai được phép tồn tại — cấu trúc-sai đã bị reject ở constructor
(Layer 1).

```text
Canonical RLE
      ↓
decode()   (on-demand runtime operation)
      ├── success                -> runtime Mask (not canonical geometry)
      └── malformed / undecodable -> INVALID validation result
```

**Layer 4 — out-of-image (tách biệt).** Geometry validity khác với image-bound validity
(xem 5.6.7). Không nhúng image dimensions vào canonical Geometry; `isWithin(imageBounds)` nhận
image bounds làm tham số. Phase 4 QA quyết định out-of-image có trở thành QA Issue và severity
hay không — đây là một quyết định của QA layer, không phải của Geometry layer.

Luồng kiến trúc đầu-cuối (end-to-end architectural flow — ranh giới kiến trúc, KHÔNG phải tuyên
bố đã triển khai):

```text
UNTRUSTED INPUT
      ↓
Parse / Normalize
      ↓
Structural validation
      ├── structural violation -> reject / throw
      ↓
Canonical Geometry
      ↓
Geometry semantic validation   (validate())
      ├── VALID
      └── DEGENERATE
      ↓
QA Engine                      (Phase 4)
      ↓
QA Issue + Severity
      ↓
Review Item
      ↓
Human Review Decision          (ACCEPT / REJECT / NEEDS_FIX)

RLE decode branch (runtime, on-demand):
Canonical RLE -> decode()
      ├── success                -> runtime Mask
      └── malformed / undecodable -> INVALID validation result
```

## 5.7 Phase 3 Geometry Acceptance Criteria (Tiêu chí nghiệm thu Phase 3)

> Đây là **tiêu chí nghiệm thu cho phần TRIỂN KHAI Phase 3**, KHÔNG phải bằng chứng rằng Phase 3
> đã được triển khai. Phase 3 hiện ở trạng thái **NOT STARTED**. Các tiêu chí được nhóm theo ranh
> giới validation của Decision #9 (xem 5.6.8): Structural rejection / Semantic validation /
> Runtime validation / Architecture.

Structural rejection (constructor / factory throws — Layer 1):

```text
□ malformed BBox rejected
□ negative BBox width / height rejected
□ non-finite coordinate rejected (BBox and Polygon)
□ malformed polygon structure rejected (not an array / malformed point)
□ fewer than 3 distinct polygon points rejected
□ consecutive duplicate polygon points rejected
□ malformed RLE structure rejected (bad size structure / dimensions, bad counts type)
```

Semantic validation (validate() on a canonical object — Layer 2):

```text
□ zero-dimension BBox => DEGENERATE
□ zero-area polygon => DEGENERATE
□ collinear polygon => DEGENERATE
□ self-intersection detected on non-adjacent edges (approved semantics)
□ BBox x2/y2 exclusive (x2 = x + width, y2 = y + height); derived area / bounds computed
□ result status uses VALID / DEGENERATE / INVALID
```
Runtime validation (boundary / on-demand operation — Layer 3):

```text
□ malformed / undecodable RLE decoding => INVALID result
□ successful RLE decoding => runtime Mask (not canonical geometry)
```

Architecture (Decision #9 boundary):

```text
□ canonical Geometry never stores structurally malformed data
□ Geometry validation assigns no QA severity
□ Geometry validation creates no Review decision
□ out-of-image remains separate from structural validity
□ canonical geometry independent from raw COCO
□ RLE preserved as RLE (no RLE -> Polygon canonical conversion)
□ viewer transform does not mutate canonical coordinates
```

# 8. Review Workflow (Luồng review)

Status:

```text
UNREVIEWED
IN_REVIEW
REVIEWED
```

Decision:

```text
ACCEPT
REJECT
NEEDS_FIX
```

Valid combinations:

| Status | Decision |
|---|---|
| UNREVIEWED | NULL |
| IN_REVIEW | NULL |
| REVIEWED | ACCEPT |
| REVIEWED | REJECT |
| REVIEWED | NEEDS_FIX |

State machine:

```text
UNREVIEWED
     │ start
     ▼
IN_REVIEW
     │ submit(decision)
     ▼
REVIEWED
```

Việc đóng trình duyệt không đồng nghĩa với REVIEWED.

## 8.1 NEEDS_FIX

NEEDS_FIX không tự động chỉnh sửa annotation.

```text
Reviewer
 ↓
NEEDS_FIX
 ↓
Export NEEDS_FIX
 ↓
External annotation fix
 ↓
New DatasetVersion
 ↓
QA
 ↓
```

# 23. Business Invariants (Bất biến nghiệp vụ)

## Dataset / Version

```text
INV-01
(dataset_id, version_number) is unique.

INV-02
parent_version_id, if present, belongs to the same Dataset.

INV-03
A version cannot be its own parent.

INV-04
Version lineage cannot contain cycles.

INV-05
READY DatasetVersion is immutable.
```

## Image / Annotation

```text
INV-06
Annotation belongs to exactly one DatasetVersion.

INV-07
Annotation.image_id references an Image in the same DatasetVersion.

INV-08
Image paths are relative paths, not machine-specific absolute paths.
```

## QA

```text
INV-09
QAIssue belongs to its QARun and DatasetVersion.

INV-10
If QAIssue.annotation_id exists, the annotation belongs to the same version.

INV-11
QA severity never directly becomes a human decision.
```

## Review

```text
INV-12
UNREVIEWED → decision must be NULL.

INV-13
IN_REVIEW → decision must be NULL.

INV-14
REVIEWED → decision is REQUIRED.

INV-15
Successful review submission creates ReviewHistory.

INV-16
Successful review submission creates AuditEvent.

INV-17
ReviewHistory is append-only.

INV-18
Review does not mutate annotation geometry/category.
```

## Version / Review

```text
INV-19
A ReviewItem always belongs to exactly one DatasetVersion.

INV-20
A new DatasetVersion creates a new review context.

INV-21
An old ACCEPT decision is not automatically current for a new version.
```

## Export

```text
INV-22
Export is read-only with respect to the dataset.

INV-23
Every ExportJob stores its filter snapshot.

INV-24
Export artifacts are linked to the ExportJob.
```

## Storage

```text
INV-25
SQLite stores application/domain state.

INV-26
Filesystem stores image and artifact binaries.

INV-27
Images are not stored as SQLite blobs in V2.

INV-28
Audit events are append-only.
```

## Geometry / Viewer

```text
INV-29
Canonical geometry uses IMAGE_PIXEL coordinates.

INV-30
Viewer zoom/pan does not mutate canonical geometry.

INV-31
RLE segmentation retains RLE semantics.

INV-32
Storage JSON representation is not the Domain representation.
```

## Review grouping

```text
INV-33
Multiple QA issues for the same annotation/version normally map to one ReviewItem.

INV-34
Annotation grouping uses:
(datasetVersionId, imageId, annotationId).

INV-35
Image-level grouping uses:
(datasetVersionId, imageId, null).
```

## Progress

```text
INV-36
Review progress counts only REVIEWED ReviewItems.
IN_REVIEW is not completed.
```

## Geometry (Phase 3 contract)

```text
INV-37
BBox x2/y2 are exclusive derived boundaries: x2 = x + width, y2 = y + height.
The canonical source of truth remains x, y, width, height.

INV-38
A BBox with width == 0 or height == 0 (finite, non-negative) is DEGENERATE, not INVALID.
Negative or non-finite BBox dimensions are INVALID.

INV-39
Polygon validity requires at least 3 DISTINCT points; repeated points do not
increase the distinct-point count.

INV-40
Consecutive duplicate polygon points are an INVALID polygon structure
(the logical-closure endpoint is the only permitted duplicate-endpoint case).

INV-41
Out-of-image status is separate from structural geometry validity; canonical
geometry does not embed image dimensions.

INV-42
RLE segmentation remains RLE in canonical storage and is never canonicalized into
Polygon; a decoded mask is a runtime-only artifact, not the canonical persisted geometry.

INV-43
Geometry validation yields derived facts only (VALID / DEGENERATE / INVALID plus issue
codes) and carries no QA severity or review/human decision.

INV-44
A successfully constructed canonical Geometry object cannot hold structurally invalid data;
structural violations (negative/non-finite BBox, malformed/too-few/consecutive-duplicate
polygon points, malformed RLE size/counts) are rejected at construction (constructor/factory
throws), not represented as a validate() status.

INV-45
Semantic degeneracy is distinct from structural rejection: a DEGENERATE geometry is a valid
canonical object that validate() flags as geometrically degenerate, whereas a structural
violation never becomes a canonical object at all.

INV-46
A validation INVALID status denotes a validation boundary or runtime operation (e.g. RLE
decode()) that cannot establish a valid geometry result; it does not imply that a structurally
invalid canonical Geometry object exists.
```

# 24. Atomic Review Submit (Submit review nguyên tử)

Successful submit MUST behave as one transaction:

```text
BEGIN
    Update ReviewItem
    Insert ReviewHistory
    Insert AuditEvent
COMMIT
```

Any failure:

```text
ROLLBACK
```

The system must not leave a partially committed review.

# 27. Implementation Principles (Nguyên tắc triển khai)

1. **Canonical model first**

```text
COCO
 ↓
Adapter
 ↓
Canonical Domain Model
 ↓
Everything else
```

2. **QA is not decision**

```text
QA Signal
   ↓
Human inspection
   ↓
Human decision
```

3. **Version is immutable**

```text
Fix
 ↓
New Version
```

4. **Viewer is not source of truth**

```text
Canonical Geometry
       ↓
Viewer
```

5. **History is append-only**

```text
Current state = mutable
History = immutable
Audit = immutable
```

6. **Business transactions are atomic**

Review submission and dataset import must not leave partially committed state.
